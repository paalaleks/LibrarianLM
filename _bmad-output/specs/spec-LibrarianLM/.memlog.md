- (direction) Create a lean canonical spec from the finalized PRD and architecture spine; preserve all architecture AD identifiers unchanged by adopting the spine as a companion.
- (direction) The PRD and addendum remain adopted companions because their detailed requirement consequences and terminology are load-bearing downstream.
- (decision) The product exists to produce useful, attributable literary-translation drafts through visible staged judgments while preserving explicit failure, structure, reproducibility, and human editorial authority.
- (capability) CAP-1 Prepare a translation run: an operator can classify book-owned content, create stable Source Units, confirm editorial guidance, and freeze a signed Prepare Package; success is a reproducible ready-for-confirmation package or a typed blocked report with no unresolved unsupported content.
- (capability) CAP-2 Run attributed translation: the system can generate contrasting proposals, evaluate them, route only weak units through bounded local recovery, and commit eligible Machine Finals; success is exactly one attributed Machine Final or explicit Failed Unit for every required Source Unit.
- (capability) CAP-3 Assemble and validate: the system can deterministically rebind committed values into Canonical Source HTML and independently validate structure, language, terminology, directionality, accessibility, and completeness; success is an eligible Translation Draft only when all blocking checks pass.
- (capability) CAP-4 Review without erasing provenance: an editor can inspect source, proposals, evaluations, recovery, and Machine Final, then record Human Edits and book-level findings; success is a reviewed export whose selected values remain linked to immutable machine history.
- (capability) CAP-5 Compare runs and qualify the pilot: a method maintainer can reject non-equivalent comparisons and measure recovery, compliance, edit burden, and usefulness under frozen methods/protocols; success is a reproducible comparison or evaluation report that discloses all material differences and evidence limitations.
- (capability) CAP-6 Orchestrate composable workflows: an operator can confirm one valid package and let independently invocable workflows execute automatically to an explicit terminal state; success is resumable artifact handoff with actionable failure and no dependence on private prompt or provider internals.
- (constraint) Only operator-confirmed public-domain works are accepted for live translation; the declaration is bound to the exact Canonical Source HTML digest.
- (constraint) Canonical Source HTML, Machine Finals, artifact history, and architecture AD identifiers are immutable within their declared scope; changes create new versioned artifacts rather than overwrite history.
- (constraint) Models may author target-language values only; source structure, markup, identifiers, order, placement, and projections remain deterministic system-owned data.
- (constraint) Workflow boundaries use versioned immutable artifacts and explicit terminal outcomes; no hidden shared mutable state or silent fallback may make an incomplete run appear complete.
- (constraint) Processing completion, translation completeness, deterministic compliance, human review, and publication readiness are orthogonal states; none implies another.
- (constraint) After operator confirmation the automatic trajectory has no per-unit human approval; literary judgment occurs afterward through the Review capability.
- (constraint) Deterministic-foundation work may proceed now; live generation, human usefulness evaluation, and release certification remain blocked by the entry gates in the PRD and architecture companion.
- (constraint) All i18n pipeline implementation code lives under src/i18n-pipeline and conforms to every AD in the adopted architecture spine.
- (decision) Non-goals: autonomous publication readiness, use of Literal Anchors as finals, second full-book recovery, translation of reader chrome, a general translation-management UI, public multilingual publishing/SEO, EPUB or XLIFF export, and automated book-level literary certification in MVP.
- (decision) Primary success requires 100 percent exact required-unit placement and 100 percent Machine Final provenance; deterministic stages produce zero unexplained differences for identical frozen inputs and versions.
- (decision) Pilot usefulness succeeds only if qualified-editor median review-and-edit time is at least 30 percent lower than the frozen single-pass baseline with no increase in critical residual errors; recovery and editorial-burden distributions are reported rather than optimized blindly.

- (question) Which qualified-editor sample, assignment/blinding design, gold subset, severity rubric, timing protocol, and Baseline Method will populate the first Editor Evaluation Protocol?
