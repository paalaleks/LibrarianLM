# PRD: EPUB to Single-Page HTML Reader

## 0. Document Purpose

This PRD defines an internal skill and deterministic converter that turn an uploaded EPUB Input into one self-contained Reader Artifact. It is intended for product, UX, architecture, implementation, and evaluation work in LibrarianLM. Requirements are grouped by feature with globally stable IDs, and §12 records whether assumptions remain. The source brief is `docs/brief/html-epub-skill-brief.md`. The existing `src/epub-html/scripts/template.html` is an authoritative design input, not a disposable prototype. Implementation details and standards notes live in `addendum.md`.

## 1. Vision

The product gives a person who has an EPUB Input a faithful, portable reading copy without requiring an EPUB application, network access, or a multi-file export. The entire book becomes one continuous, searchable, printable HTML surface with a persistent Navigation Tree and a Book Rail that makes chapter scale and reading position visible.

The skill orchestrates a deterministic conversion; it does not act as an editor. Book content is extracted, cleaned for offline use, and connected, but never rewritten, summarized, or retyped by a language model. Given the same EPUB Input bytes, Converter version, Reader Template version, and configuration, conversion produces byte-identical Reader Artifact bytes.

Every Reader Artifact shares one restrained design system. The experience should feel like a book taken apart and reassembled as one legible surface: cool daylight paper, quiet typography, strong information hierarchy, and one expressive element—the data-driven Book Rail. A shelf of converted books should look like a coherent set.

## 2. Target User

### 2.1 Jobs To Be Done

- When I upload an EPUB Input in chat, give me one offline Reader Artifact I can download and open directly.
- Preserve the source book’s reading order, semantic structure, links, and text while removing non-portable behavior.
- Let me understand the book’s scale, navigate its structure, and see my current position without page-turning UI.
- Let me search, use keyboard navigation, switch theme, invoke browser reader mode, and print using ordinary browser capabilities.
- When the EPUB Input cannot be converted faithfully, tell me what happened in plain language rather than silently omitting content.
- As a maintainer or design reviewer, let me review and evolve one standalone Reader Template rather than UI fragments generated by conversion code.

### 2.2 Non-Users in MVP

- Readers who need a paginated or page-turn simulation.
- Publishers seeking an EPUB editor, proofing system, or round-trip conversion workflow.
- Users seeking faithful reproduction of comics, magazines, or other fixed-layout publications.
- Users seeking decryption or circumvention of protected publications.

### 2.3 Key User Journey

- **UJ-1. Nora converts a book in chat and reads it offline.** Nora uploads an EPUB Input to the LibrarianLM chat. The skill recognizes the file, runs the Converter, and returns one named Reader Artifact plus a Conversion Summary. The summary identifies the title, author, chapter count, word count, estimated reading time, output size, and any warnings or fallbacks. Nora downloads the file, opens it without a network connection, scans the title facts, uses the Navigation Tree and Book Rail to jump through the book, follows footnotes, toggles dark mode, searches, and prints. If the input is protected or unsupported, the skill stops and gives Nora an actionable explanation instead of a partial file.

## 3. Glossary

- **EPUB Input** — The uploaded `.epub` byte stream supplied to the skill.
- **Converter** — The deterministic local program that validates an EPUB Input, transforms book content, and fills the Reader Template.
- **Reader Template** — The complete, standalone HTML design source containing all reader markup, styling, and behavior. The canonical source is `src/epub-html/scripts/template.html`.
- **Reader Artifact** — The single self-contained `.html` file produced from one EPUB Input.
- **Spine Document** — A content document referenced by the EPUB package spine; spine order defines default reading order.
- **Navigation Tree** — The book’s hierarchical table of contents as represented in the Reader Artifact, visually limited to two levels in MVP.
- **Book Rail** — The Navigation Tree’s data-driven chapter scale and active-position indicator.
- **Title Block** — The generated opening region containing title, author, chapter count, word count, and estimated reading time.
- **Conversion Summary** — The skill’s human-readable report of detected metadata, output facts, warnings, fallbacks, or failures.
- **Supported EPUB** — An EPUB Input the MVP can convert without an unsupported protection or content condition, as bounded by this PRD.
- **Source Content** — Book-authored text, semantics, identifiers, links, and supported embedded resources extracted from the EPUB Input.

## 4. Features

### 4.1 Chat Orchestration and Delivery

**Description:** The skill recognizes an EPUB Input, invokes the Converter without asking a language model to reproduce Source Content, and returns either exactly one Reader Artifact with a Conversion Summary or an actionable failure. This realizes UJ-1.

#### FR-1: Trigger conversion for uploaded EPUB

The skill can identify an uploaded `.epub` as an EPUB Input and invoke the Converter with that file.

**Consequences (testable):**

- A chat turn containing a valid uploaded `.epub` starts the conversion workflow.
- The model does not transcribe, summarize, translate, or rewrite Source Content.
- Non-EPUB uploads do not trigger the workflow solely because their filenames resemble book titles.

#### FR-2: Deliver one artifact or one clear failure

The skill can return exactly one slug-named Reader Artifact for a successful conversion, or stop without presenting a partial Reader Artifact when conversion fails.

**Consequences (testable):**

- A successful conversion is presented as `<slugified-title>.html`.
- The Reader Artifact is written to the host’s designated downloadable output location.
- A failed conversion reports the reason and any appropriate next action in plain language.

#### FR-3: Report conversion facts and warnings

The skill can provide a Conversion Summary for every attempted conversion.

**Consequences (testable):**

- Success includes detected title, author when present, Spine Document count, total word count, estimated reading time at 250 words per minute, and Reader Artifact size.
- The summary identifies Navigation Tree fallback use, fixed-layout classification, unsupported or omitted content, and large extracted text above 5 MB.
- The summary does not claim fidelity for content the Converter omitted or could not interpret.

### 4.2 EPUB Validation and Reading Order

**Description:** The Converter treats the EPUB Input package and spine as authoritative for content order, identifies navigation sources, and reports protected or structurally invalid inputs clearly. This realizes the conversion portion of UJ-1.

#### FR-4: Resolve the EPUB package deterministically

The Converter can locate the EPUB package document and derive metadata, resources, and Spine Documents in package spine order.

**Consequences (testable):**

- Every included Spine Document appears in the Reader Artifact in deterministic package spine order.
- Repeated spine references remain repeated rather than being deduplicated.
- Missing or invalid package metadata produces a diagnostic instead of an unhandled exception.
- MVP includes all linear Spine Documents and transitively includes non-linear Spine Documents only when linked from included content.

#### FR-5: Build the Navigation Tree

The Converter can derive the Navigation Tree from the EPUB navigation document, then legacy NCX navigation, then Spine Document headings.

**Consequences (testable):**

- A usable EPUB navigation document takes precedence when present.
- Legacy NCX navigation is used when a usable navigation document is absent.
- If neither source is usable, the first `h1` or `h2` in each Spine Document supplies its deterministic fallback label; a stable generic label is used when neither heading exists.
- The Conversion Summary identifies when fallback navigation was required.

#### FR-6: Detect protected and unsuitable publications

The Converter can distinguish unsupported encrypted publication content from standard EPUB font obfuscation and can identify fixed-layout publications.

**Consequences (testable):**

- Unsupported encrypted publication content stops conversion with a clear “no decryption attempted” message.
- Standard font-obfuscation metadata is not by itself reported as DRM.
- A fixed-layout EPUB Input produces a poor-fit warning and a best-effort conversion rather than an implied fidelity guarantee.
- Obfuscated embedded fonts are discarded because the Reader Template intentionally uses offline system font stacks.

### 4.3 Faithful Content Transformation

**Description:** The Converter concatenates supported Source Content into a continuous semantic document, preserves relationships needed for reading, and removes source behavior that cannot be carried into a deterministic offline Reader Artifact.

#### FR-8: Concatenate Spine Documents without rewriting prose

The Converter can place each included Spine Document into a uniquely identified chapter section in order without language-model modification of its prose.

**Consequences (testable):**

- Reader Artifact chapter count matches the included spine occurrence count.
- Headings, paragraphs, blockquotes, lists, tables, emphasis, strong emphasis, language direction, and footnote semantics are preserved where valid and supported.
- The transformation does not introduce summaries, corrections, translations, or invented headings.

#### FR-9: Resolve internal navigation

The Converter can rewrite supported intra-book links and identifiers so navigation continues to work in one HTML document.

**Consequences (testable):**

- Every Navigation Tree link resolves to one identifier in the Reader Artifact.
- Footnote returns and cross-chapter fragment links resolve within the Reader Artifact.
- Generated identifiers are collision-free and deterministic.
- No unresolved relative document path remains in an HTML navigation attribute.

#### FR-10: Clean Source Content for offline output

The Converter can remove source scripts, inline event handlers, and external stylesheets while preserving semantic Source Content.

**Consequences (testable):**

- Source scripts, inline event handlers, and external stylesheets are absent from the Reader Artifact.
- The Reader Artifact contains no references that cause external requests when opened.
- The reader behavior supplied by the Reader Template remains functional after Source Content cleanup.

#### FR-11: Omit images and external resources explicitly

The Converter removes images, multimedia, source styling, and remote resources while preserving meaningful surrounding semantic markup; it never fetches a remote resource during conversion or reading.

**Consequences (testable):**

- Opening the Reader Artifact offline causes zero external requests.
- The Conversion Summary reports omission counts by category.
- Image and media elements are absent, and empty wrappers created by their removal are not retained.

### 4.4 Canonical Reader Experience

**Description:** The Reader Template supplies the complete reading interface and consistent visual identity. The Converter fills content slots but does not generate or duplicate reader UI. The existing template is evolved in place inside the canonical `src/epub-html/` subtree.

#### FR-12: Render through one canonical Reader Template

The Converter can fill named Reader Template slots for book metadata, the Navigation Tree, the Title Block, and chapter sections without generating independent UI markup, CSS, or JavaScript.

**Consequences (testable):**

- `src/epub-html/scripts/template.html` opens directly as a working design-review artifact with placeholder content.
- Every Reader Artifact includes the Reader Template’s complete inline styling and behavior.
- A visual or interaction change is made once in the Reader Template rather than duplicated in Converter string construction.
- All EPUB-to-HTML skill, converter, template, and evaluation code lives under `src/epub-html/`.

#### FR-13: Present a continuous reader with a collapsible sheet

The Reader Template can present one continuous full-width reading surface with its Navigation Tree in the canonical modal left sheet at every viewport size.

**Consequences (testable):**

- The sheet is hidden by default and overlays rather than reflows the full-width reading region.
- At every viewport size, a persistent Contents toggle, close control, `c` shortcut, and Escape can hide or restore it.
- The sheet independently scrolls; while open, the background is inert and scroll-locked behind a scrim, keyboard focus is trapped, and focus returns to its origin on close.
- The toggle exposes correct `aria-expanded` state and reduced-motion preferences are honored.
- Below 900 px, sheet width leaves a small viewport edge visible and the reading region uses 1 rem gutters.
- Body copy is capped at a readable 68-character measure.
- Print output hides reader chrome and begins chapters on new pages.

#### FR-14: Communicate book scale and position

The Reader Template can use real book data to render the Title Block and Book Rail.

**Consequences (testable):**

- The Title Block displays real title, author when present, chapter count, total word count, and estimated reading time.
- The Navigation Tree has a Title Block destination without a chapter rail marker.
- Chapter markers have a deterministic visual weight proportional to chapter word count.
- The active chapter and current position update as the reader scrolls.
- Source navigation deeper than two levels is visually flattened to two levels while retained destinations remain reachable.

#### FR-15: Support reader preferences and keyboard use

The Reader Template can honor system preferences and explicit reader choices.

**Consequences (testable):**

- Theme defaults to `prefers-color-scheme`; an explicit sidebar control and the `d` key toggle it.
- The explicit theme choice persists locally when browser storage is available and degrades safely when it is unavailable.
- All Navigation Tree links and controls are reachable by keyboard and expose a visible focus indicator.
- Under `prefers-reduced-motion`, smooth scrolling and animated position movement are disabled.

#### FR-16: Preserve semantic browser affordances

The Reader Artifact can expose meaningful document structure to browsers and assistive technology.

**Consequences (testable):**

- The Reader Artifact uses landmarks, a labeled navigation region, one main region, article structure, and valid heading relationships.
- Source language, text direction, image alternative text, and page-break semantics are preserved where available.
- Browser search, selection, reader mode, and printing remain usable without a custom substitute.

### 4.5 Deterministic Conversion and Diagnostics

**Description:** Determinism is a user-visible product contract. A fallback environment must not silently change the Reader Artifact, and diagnostics must explain material deviations.

#### FR-17: Produce byte-identical output

The Converter can produce byte-identical Reader Artifact bytes when EPUB Input bytes, Converter version, Reader Template version, and configuration are identical.

**Consequences (testable):**

- Repeated conversions produce the same SHA-256 digest.
- Output contains no timestamps, random identifiers, machine-specific absolute paths, locale-dependent formatting, or nondeterministic traversal order.
- Text encoding, line endings, attribute ordering, identifier generation, and diagnostic ordering are stable.

#### FR-18: Maintain fallback-path parity

The Converter can complete a well-formed Supported EPUB with or without optional third-party parsing dependencies and produce identical Reader Artifact bytes.

**Consequences (testable):**

- The primary and fallback paths pass the same conformance fixtures.
- A path change does not alter output bytes for those fixtures.
- If parity cannot be maintained for an input, conversion stops or reports a defined unsupported condition rather than returning divergent output as equivalent.

## 5. Cross-Cutting Non-Functional Requirements

### NFR-1: Offline Integrity

The Reader Artifact must be one file with inline styles, reader behavior, and supported resources. It must make zero network requests when opened and require no framework, CDN, installation, or build step.

### NFR-2: Trusted-Source Boundary

EPUB Inputs are assumed to come from a known, trusted source. The product does not require adversarial archive, XML, or markup defenses. Source scripts, event handlers, and external stylesheets are still removed to satisfy deterministic, portable, zero-network output—not to establish a security sandbox.

### NFR-3: Accessibility

The Reader Template’s own interface should meet WCAG 2.2 AA for keyboard operation, visible focus, contrast, text resize, and reflow. The Converter must preserve available Source Content accessibility metadata but must not invent missing semantics or claim that an inaccessible source became accessible.

### NFR-4: Reliability and Diagnostics

Expected unsupported inputs must produce structured, plain-language failures or warnings. Conversion must not silently omit an entire Spine Document or claim success when Navigation Tree destinations do not resolve.

### NFR-5: Scale

The Converter must still produce one Reader Artifact when extracted text exceeds 5 MB. Large-output size must be reported. MVP has no separate performance SLA beyond successful conversion and an interactively usable Reader Artifact on the agreed test corpus.

### NFR-6: Maintainability

The Reader Template is the single source of truth for reader UI and remains directly browser-reviewable. Product code is confined to `src/epub-html/`. Evaluation fixtures and assertions accompany behavior changes.

## 6. Aesthetic and Interaction Guardrails

- The visual concept is a book reassembled as one continuous surface, not an imitation of pagination.
- The palette remains cool and slightly green, closer to laid paper under daylight than parchment. It deliberately avoids the conventional cream-page, display-serif, terracotta-accent reading-app aesthetic.
- Typography uses offline system stacks with body serif, interface sans, and utility mono roles. Exact tokens and stacks are recorded in `addendum.md` and the Reader Template.
- The Book Rail is the signature element and must express real chapter weight and current position; it is not decorative.
- Everything outside the Book Rail stays quiet: restrained rules, spacing, type hierarchy, and motion.
- One shared accent and design identity apply to every Reader Artifact in MVP; per-book accent overrides are out of scope.

## 7. Constraints and Guardrails

### 7.1 Content Fidelity

- Source Content may be transformed only as required for self-contained embedding, deterministic identifiers, and working in-page navigation.
- The skill must never ask a language model to regenerate book prose.
- The Conversion Summary must disclose material omissions and degraded handling.

### 7.2 Repository Boundary

- All product deliverables—skill definition, Converter, Reader Template, and evaluations—must live under `src/epub-html/`.
- No parallel EPUB-to-HTML implementation may be added at repository root or under another `src/` package.

### 7.3 Dependency and Runtime Boundary

- The Reader Artifact has no runtime dependencies.
- Conversion must remain available without package installation by using a standard-library fallback with output parity for well-formed Supported EPUBs.
- Concrete library and runtime choices are architecture concerns recorded in `addendum.md`.

## 8. Non-Goals

- Pagination, page-turn animations, reading accounts, cloud sync, highlights, annotations, or library management.
- Editing, correcting, translating, summarizing, or restyling Source Content on a per-book basis.
- Decrypting DRM or bypassing publication protections.
- Pixel-identical reproduction of publisher styling across operating systems.
- Faithful fixed-layout, comic, magazine, audio, video, or interactive EPUB playback.
- Network retrieval of remote publication resources.
- Per-book themes, accents, fonts, or generated reader UI in MVP.
- A public conversion API, web service, or general-purpose EPUB SDK.

## 9. MVP Scope

### 9.1 In Scope

- Chat trigger, local deterministic conversion, Conversion Summary, and one downloadable Reader Artifact.
- EPUB 2/3 text-focused packages with spine reading order and navigation document, NCX, or heading fallback.
- Semantic text, tables, lists, blockquotes, internal links, and footnotes; images and multimedia are omitted.
- Source-content cleanup and explicit local or external resource handling.
- Responsive Reader Template, collapsible sheet, Title Block, Navigation Tree, Book Rail, light/dark theme, keyboard access, reduced motion, and print support.
- Existing `src/epub-html/scripts/template.html` as the canonical UI artifact.
- Determinism and primary/fallback parity tests.
- Test corpus spanning a clean deep-TOC book, a structurally rich book, and a no-navigation book.

### 9.2 Out of Scope for MVP

- Fixed-layout fidelity beyond warning and best effort.
- Multimedia and interactive publication playback.
- Preservation of publisher scripts, external stylesheets, embedded fonts, or remote resources.
- Preservation of images, SVG, audio, video, canvas content, or embedded browsing resources.
- Per-book visual customization.
- Editing or round-tripping back to EPUB.
- Hosted storage, sharing, accounts, or synchronization.

## 10. Success Metrics

### Primary

- **SM-1: Deterministic success.** 100% of Supported EPUB fixtures produce identical SHA-256 digests across three repeated conversions with fixed input, Converter, Reader Template, and configuration; primary and fallback paths match. Validates FR-17 and FR-18.
- **SM-2: Structural fidelity.** 100% of Supported EPUB fixtures have included chapter counts matching included spine occurrences, and 100% of Navigation Tree and retained internal links resolve to unique Reader Artifact identifiers. Validates FR-4, FR-5, FR-8, and FR-9.
- **SM-3: Offline integrity.** 100% of Supported EPUB fixtures produce no external requests and retain no source scripts, event handlers, or external stylesheets. Validates FR-10 and FR-11.

### Secondary

- **SM-4: Reader integrity.** The Reader Artifact test set opens with zero uncaught browser console errors and passes keyboard, focus, theme persistence, reduced-motion, responsive breakpoint, search, and print checks. Validates FR-13 through FR-16.
- **SM-5: Transparent handling.** Every protected, fixed-layout, large, fallback-navigation, resource-omission, and unsupported fixture produces the expected warning or failure classification with no silent whole-chapter omission. Validates FR-3, FR-6, and NFR-4.
- **SM-6: Template governance.** Automated checks confirm that every Reader Artifact derives its reader chrome from the canonical Reader Template and that all product files remain under `src/epub-html/`. Validates FR-12 and NFR-6.

### Counter-Metrics

- **SM-C1: Do not optimize conversion rate by hiding degradation.** Unsupported inputs and material omissions must be reported even if doing so lowers the nominal success rate. Counterbalances SM-1 and SM-5.
- **SM-C2: Do not optimize byte identity by discarding meaningful content.** Determinism cannot be achieved by silently removing supported Source Content or navigation. Counterbalances SM-1 and SM-2.
- **SM-C3: Do not optimize visual fidelity by weakening offline integrity.** Publisher behavior and styling stay subordinate to deterministic cleanup and zero-network requirements. Counterbalances SM-3 and SM-4.
