# Completeness and Feasibility Review — EPUB to Single-Page HTML Reader

## Overall verdict

The PRD is strong on reader UX, fidelity intent, and offline/determinism *goals*, but it is **not development-ready as a conversion contract**. §11 (“No phase-blocking open questions remain”) and §12 (“No unresolved assumptions remain”) close the document while CLI vs skill I/O, Conversion Summary shape, slug/word-count rules, parser `auto` behavior, SKILL.md host, and several FR contradictions are still unspecified. An implementer following only this PRD plus addendum would have to invent product decisions or silently import them from the brief / implementation spec.

## Findings

- **critical** False closure of open questions (§11, §12) — The PRD states “No phase-blocking open questions remain” and “No unresolved assumptions remain,” yet the brief’s output contract (CLI flags, atomic write, JSON summary fields, `/mnt/user-data/outputs/`, slug, parser `auto`) is not restated as FRs, and `.memlog.md` still lists assumptions as “needs confirmation,” including the superseded “MVP embeds safe raster images.” *Fix:* Reopen §11/§12 with an explicit decision list (or promote those contracts into numbered FRs) and reconcile or archive stale memlog assumptions.

- **critical** CLI vs skill vs Conversion Summary contract (FR-2, FR-3, glossary, brief §5, addendum B) — Glossary: Conversion Summary is “the skill’s **human-readable** report.” FR-3 consequences are prose facts. Brief §5: “success writes the file atomically and emits **one JSON Conversion Summary**” with fields including `navigation_source`, `parser path`, warnings, and omission counts. Addendum B shows `convert.py book.epub --out out.html` and `/mnt/user-data/outputs/<slugified-title>.html`, while FR-2 only says “the host’s designated downloadable output location.” No FR requires `--template`, `--parser auto|ebooklib|stdlib`, exit codes, stdout vs chat rendering, or atomic replace. *Fix:* Split two testable contracts: Converter CLI (argv, exits, JSON schema, atomic `--out`) and skill presentation (where the file is written, how JSON is rendered in chat). Do not leave JSON vs prose unresolved.

- **critical** Dual-parser byte identity is underspecified and likely infeasible as written (FR-17, FR-18, addendum B, brief §2) — FR-17 requires “byte-identical Reader Artifact bytes” and “locale-dependent formatting” forbidden. FR-18 requires primary and fallback paths to “produce identical Reader Artifact bytes” for “well-formed Supported EPUB.” Addendum B adds `auto` that “compares their normalized intermediate representations before serialization” and “any disagreement fails without an output file”—this `auto` mode is **not** an FR. “Well-formed Supported EPUB” is undefined relative to HTML5 implied tags, namespaces, entity decoding, and `html.parser` vs BeautifulSoup. *Fix:* Make IR comparison, `--parser` values, and fail-on-disagreement FRs; define the fixture set that *must* match vs inputs that are `unsupported`/`parser-disagreement`; do not claim HTML-tree byte identity without a frozen IR+serializer spec in the PRD or a named architecture doc.

- **critical** Image omission vs preserved image alt (FR-11, FR-16, §9.1, brief §9) — FR-11: “Image and media elements are absent.” §9.1: “images and multimedia are omitted.” Brief confirmed decision: “Ignore all images and multimedia.” FR-16: “Source language, text direction, **image alternative text**, and page-break semantics are preserved where available.” No FR says whether alt becomes visible text, a caption, or is dropped with the `img`. *Fix:* Resolve one product rule (omit elements and drop alt vs promote alt to text) and delete or rewrite the conflicting FR-16 clause.

- **high** Missing FR-7 and missing FRs for confirmed pipeline behavior (Features §4.2–4.3, §11, addendum H) — IDs jump **FR-6 → FR-8**. Confirmed in §11 / addendum H but **not** FRs: transitive non-linear inclusion with visited-set/cycle handling; “ambiguous repeated targets to the first included occurrence with a warning”; malformed-body recovery only when normalized parsers agree; atomic fail on package/spine unreadability or parser disagreement; no conversion manifest. Implementers can ship FR-4/FR-8 without those rules. *Fix:* Assign FR-7 (or new FRs) to inclusion-closure, malformed recovery, and atomic failure; keep numbering stable once assigned.

- **high** “Usable” navigation is undefined (FR-5) — Consequences: “A **usable** EPUB navigation document takes precedence”; “Legacy NCX … when a **usable** navigation document is absent”; “If neither source is **usable**…” Presence, empty TOC, broken `href`s, landmarks-only nav, and NCX with zero navPoints are not distinguished. NFR-4 forbids claiming success when “Navigation Tree destinations do not resolve,” but FR-5 does not say empty-but-present nav is unusable. *Fix:* Define usable (e.g. at least one resolvable content target after rewrite) and the exact precedence test.

- **high** Fixed-layout “best-effort” is not a conversion rule (FR-6, §8, §9.2, brief §6) — FR-6: “A fixed-layout EPUB Input produces a poor-fit warning and a **best-effort** conversion rather than an implied fidelity guarantee.” Non-goals reject “faithful fixed-layout.” No definition of extractable text, what to do if there is no readable text, XHTML vs bitmap spreads, or whether SM-1 still requires hash stability on those fixtures. *Fix:* Replace “best-effort” with observable rules (convert extractable spine XHTML with the same omit-images policy; fail if no text; never claim layout fidelity).

- **high** Slug, missing title, and filename collisions unspecified (FR-2, UJ-1) — Success is “`<slugified-title>.html`.” No Unicode/NFKD rules, empty/`dc:title` missing, multi-title, collision with an existing output, or reserved Windows names. Brief uses `<slug>`; addendum uses `<slugified-title>`. *Fix:* Specify slug algorithm, `Untitled`/`untitled` fallback, and overwrite vs fail policy as FRs (product decision currently unresolved).

- **high** Word count, chapter count, and reading-time formatting unspecified (FR-3, FR-14, FR-17, NFR-5) — FR-3: “total word count, estimated reading time at 250 words per minute”; FR-14: rail “proportional to chapter word count.” No tokenizer (whitespace split vs Unicode word boundaries), whether markup/alt/omitted media text counts, whether Title Block and summary use the same integer, ceiling vs floor of minutes, or display locale (“1,234” vs `1234`) despite FR-17 banning “locale-dependent formatting.” “Chapter count” vs “Spine Document count” vs Navigation Tree entries may diverge when non-linear items are included or TOC is flatter than spine. *Fix:* Define one word-count function, one chapter-count definition (included spine occurrences), and a locale-stable facts string.

- **high** Chat upload vs trusted-source boundary (UJ-1, JTBD, NFR-2, addendum E) — UJ-1: “Nora uploads an EPUB Input to the LibrarianLM chat.” NFR-2: “EPUB Inputs are **assumed to come from a known, trusted source**. The product does not require adversarial archive, XML, or markup defenses.” A chat-triggered skill is a natural untrusted-upload surface. Cleanup is framed as offline determinism, not a sandbox. *Fix:* Name the host and operator (internal maintainer vs end-user chat) in the PRD; if chat remains the trigger, either accept residual risk explicitly or reopen NFR-2—do not leave implementers guessing.

- **high** SKILL.md host and trigger contract missing (FR-1, addendum A, brief §7) — Addendum A / brief deliver `src/epub-html/SKILL.md`, but no FR describes trigger matching (extension vs MIME vs magic bytes), when the skill may refuse non-epub, Python invocation, working directory, or which host (`/mnt/user-data/outputs` is Claude/Computer-use shaped, not a generic LibrarianLM path). FR-1: “A chat turn containing a valid uploaded `.epub` starts the conversion workflow” without defining “valid.” *Fix:* Add a skill FR: host, SKILL.md location, invocation of `convert.py`, mapping of JSON summary to chat, and “exactly one artifact.”

- **high** Source styling / class preservation contradiction (FR-10, FR-11, brief §2, addendum E) — Brief: preserve “classes, IDs, language/direction, ARIA, `epub:type`” and remove `style` attributes and source stylesheets. FR-11: remove “source styling.” FR-10: remove “external stylesheets” while “preserving semantic Source Content.” Class-based publisher styling without CSS will not render, which is fine, but “source styling” can be read as stripping `class`. *Fix:* FR-level allowlist/denylist of attributes (match brief: keep `class`/`id`/`lang`/`dir`/ARIA/`epub:type`; drop `style`, `on*`, resource attrs).

- **medium** Encryption vs font obfuscation classification incomplete (FR-6, addendum E, brief §6 table) — Brief table: “Detect `META-INF/encryption.xml`, stop.” PRD correctly says font obfuscation is not DRM, but “unsupported encrypted publication content” is not defined (which `CipherReference` URIs, encrypted fonts vs documents, partially encrypted packages). *Fix:* FR: fail only when content documents (or enough of them that reading fails) are encrypted; obfuscated fonts discarded; encryption.xml present + fonts-only is not failure.

- **medium** Identifier scheme and Navigation Tree depth (FR-9, FR-14, brief layout) — Brief layout: `id="ch-NN"` per spine document. FR-9: “Generated identifiers are collision-free and deterministic” with no scheme, padding, or source-id retention. FR-14 flattens display to two levels; FR-5 does not say nav is parsed in full then flattened. Duplicate heading fallback labels and collision with template IDs are unspecified. *Fix:* Specify occurrence-scoped IDs and parse-full/flatten-display in FR-5/FR-9.

- **medium** SVG, MathML, and “embedded browsing resources” (FR-11, §9.2, brief cleanup) — §9.2 omits “images, SVG, audio, video, canvas… or embedded browsing resources.” FR-11 lists “images, multimedia.” Inline SVG used as figures vs decorative vs text diagrams is unresolved. MathML not mentioned. *Fix:* Name omitted element list in an FR (do not leave SVG under “images” only).

- **medium** “Interactively usable” and unnamed corpus (NFR-5, §9.1, SM-4, addendum F) — NFR-5: “interactively usable Reader Artifact on the **agreed test corpus**.” Corpus is described by type (Gutenberg classic, footnotes/tables, no-nav) not by files, licenses, or size bound. SM-4 “zero uncaught browser console errors” needs a browser/engine. *Fix:* Name fixtures, provenance, Python/runtime, and what “usable” means (open, search, TOC, print) without a performance SLA if that remains the decision.

- **medium** Canonical template vs unfinished Book Rail (FR-12, FR-14, §1, addendum C) — Template is “authoritative” and “complete,” yet FR-14 requires a data-driven Book Rail and named slots that addendum C only lists “at minimum.” If the checked-in template lacks slots/rail, FR-12’s “opens directly as a working design-review artifact” and “Converter does not generate UI markup” fight each other until slot markup exists. *Fix:* State remaining template gaps as in-scope product work, not implied already-done.

- **medium** Source brief path is wrong (§0) — PRD: “The source brief is `docs/brief/html-epub-skill-brief.md`.” Actual file: `docs/brief-epub-html/html-epub-skill-brief.md`. *Fix:* Correct the path so reviewers do not treat a missing file as the brief.

- **medium** Remote `href` rewrite vs “no unresolved relative document path” (FR-9, FR-11, NFR-1) — FR-9: “No unresolved relative document path remains in an HTML navigation attribute.” FR-11 / brief: live remote URLs removed. Unclear whether `https://` bibliography links are stripped, left as-is (violates zero external requests if clicked—NFR-1 is “when opened,” not when clicked), or rewritten to inert text. *Fix:* Define allowed URL schemes in output (`#` fragments only vs keep external http(s) without prefetch).

- **low** FR-1 “filenames resemble book titles” — Testable consequence is odd and untestable without examples (`.pdf` named `Moby-Dick` vs `.epub`). *Fix:* Trigger only on `.epub` (and optionally EPUB MIME/magic); drop the resemblance clause.

- **low** Print vs continuous-surface vision (§1, FR-13) — Vision rejects page-turning UI; FR-13 print “begins chapters on new pages.” Internally consistent if print-only; worth one sentence so print CSS is not treated as a fidelity bug.

- **low** Brief ASCII layout vs modal sheet (brief §3 vs PRD FR-13) — Brief still shows a 280px persistent sidebar diagram while text and PRD require a hidden modal sheet. Risk if someone implements the diagram. *Fix:* Align brief figure with the sheet (out of scope for this PRD file except as a known mismatch).

## Notes for implementers (not product decisions)

Decisions that appear in `spec-epub-to-single-page-html-reader.md` (slug NFKD, `Untitled`, JSON fields, `ch-NNNN` IDs, parser exits) **must not be treated as PRD-approved** until §11/FRs say so. This review does not adopt them.
