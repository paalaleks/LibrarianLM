Poor

The PRD has a real product thesis, named trade-offs, and integrity invariants that architecture can use as a spine: structure stays independent of generated language, extra generation hits weak units only, and fluent output is never publication readiness. It is not ready for development of the MVP as a buildable product. status: final overclaims planning completeness while the Pilot Profile, Baseline Method, language pair, evaluation pass/fail, neighbor-context policy, required editorial inputs, and review-surface sufficiency remain unfrozen.

Adversarial and verification-gap reviews agree and add three development-blocking product holes: there is no operable copyright/provider transfer policy, Machine Final “plain value” vs HTML emphasis/placeholders is unresolved, and SM-3 / editor protocol / evaluation circularity cannot be observed. Integrity work (dummy round-trip, manifests, honest failure) can start; generation, provider calls, and usefulness measurement cannot.

Adversarial review

review-adversarial-general.md

This PRD is a well-written honesty envelope wrapped around an unbuildable first increment. It freezes stance while leaving skill inventory, artifact fields, required units, Machine Final markup, Failed Unit resolution, and the Literary Editor’s edit surface to Architecture, a future Pilot Profile, or existing surfaces that do not exist. Status final is false advertising.

critical

Pilot Profile is a certification gate, not a build gate

§0, FR-26, §8.1
A team that starts now will invent segmentation for poetry/tables/footnotes, then learn the profile excludes that class or that cost is 10× budget.
Fix: Make an approved Pilot Profile a start-of-implementation gate. Until it exists, only the deterministic dummy loop (FR-17) is in scope.
critical

No operable copyright/provider transfer policy

NFR-9, FR-26, §10
Inherit-until-defined collides with approved-before-any-transfer. Literary MVP is copyrighted books sent to multiple models.
Fix: Translation-specific data-handling FR approved with the Pilot Profile before any model call on book text.
critical

Machine Final purity vs HTML reassembly unresolved

glossary, FR-14, FR-16, FR-18
If the Final is plain text, assembly cannot place moved emphasis. If it is HTML, models emit wrappers — the failure determinism claims to prevent.
Fix: Specify payload type: plain text plus annotation map, or constrained fragment with tokens assembly rebinds.
high

Open Question 1 still blocks the method

§12 Q1, FR-9, FR-24
Literary translation depends on whether unit N sees source-only neighbors, committed targets, or nothing. Parallel batching without that policy is a different method every night.
Fix: Resolve neighbor window, source vs committed-target, freeze-at-batch vs wait-for-predecessors, and Failed Unit predecessor behavior before any generation skill is specified.
high

Required Source Unit is undefined

SM-1, FR-4, FR-15
Completeness is 100% of required units; required vs optional vs excluded vs unsupported is never defined.
Fix: Define those states with terminal effects on Translation Draft eligibility; bind the first matrix to the Pilot Profile.
high

Review/SM-3 depend on unspecified surfaces

UJ-2, FR-21–23, §8.2
The existing surface is an EPUB→HTML reader, not a provenance inspector or edit store.
Fix: Specify MVP review as a skill contract (get provenance, put Human Edit, export) or a files-plus-checklist procedure that still captures FR-27.
high

Failed Units have no resolution path

FR-15, FR-21, FR-3
One stubborn unit blocks literary review and SM-3. There is no unit-level retry, waiver, or editor-salvage path that does not mint a Machine Final.
Fix: Add Failed Unit lifecycle: retry bounds, diagnostics, whether a new run is the only fix, optional editor salvage without a complete Draft.
high

Baseline Method is a purpose, not a method

FR-27, SM-3
Single-pass of what? Critical residual error, edit magnitude, qualified editor, and clock start are undefined.
Fix: Freeze baseline treatment, shared unit inventory, editor qualification, severity taxonomy, magnitude, timing, and N/exclusion rules.
high

Skill and artifact contracts promised then refused

FR-1, FR-2, §6, §11
Must not fix schema, while FR-1 requires declared inputs, artifacts, and terminal states.
Fix: MVP skill inventory and field-level product schema for every glossary artifact — not storage layout.

FR-6, FR-3

Verification-gap review

review-verification-gap.md

Integrity FRs are largely testable. Usefulness, editor protocol, and operating bounds are not. Generic Skill Workflow implementation can proceed on integrity FRs; pilot coding of generation, detectors, and review measurement cannot without freezing the items below.

critical

SM-3 has a target without a measurement system

§9, FR-27, §13
Missing: Baseline Method identity, sample size, clocks, critical-residual definition, uncertainty, owner. FR-27 requires reporting those facts after the fact.
Fix: Freeze a Baseline Method card; require a dry run that can fail the 30% target as infeasible before implementation claims SM-3.
critical

Human-editor protocol is unspecified

FR-22, FR-27, SM-3, SM-6
No qualification, blinding, magnitude formula, or severity rubric. The 30% claim can be gamed by assignment or by showing evaluators the scores.
Fix: Publish an editor protocol as a release-qualification artifact alongside the Pilot Profile.
critical

Evaluation circularity: model scores stand in for literary done

FR-8/10/11/13/14 vs SM-C2
The only automated observers of faithfulness/naturalness are model evaluators that SM-C2 forbids treating as quality. No gold units or human spot-check sampling.
Fix: Human-rated gold subset; scores remain routing telemetry; forbid evaluator averages as release evidence.
high

Language-pair and corpus freeze happen too late

FR-26, §8.1
Residual detectors, RTL, style, and fixtures are pair-dependent. An unfrozen corpus makes SM-3 and FR-17 cherry-pickable.
Fix: Freeze pair, corpus list, and include/exclude matrix before generation, detector, and editor-protocol implementation.
high

Provider, recovery, and cost are unbounded

FR-8, FR-12, NFR-11
At least one Idiomatic Candidate with no maximum; additional Recovery Candidates with no cap; numeric budgets deferred to an unwritten profile.
Fix: Per-unit and per-run caps before any live provider call; missing caps are a failed precondition.
high

Passing/weak/compliant is unobservable while thresholds are forbidden

§4.3–4.4, §6
FR-11 and FR-15 cannot be accepted on the PRD alone; implementations will invent incompatible gates.
Fix: Versioned Translation Method as test fixture in the Pilot Profile; keep numbers out of the generic contract.
high

Data-governance inheritance is untestable

NFR-9, FR-26
No policy name, version, or location. If the parent policy is silent on copyrighted literary text, FR-26 has no fail test.
Fix: Cite the runtime policy artifact or mark translation-specific policy as a Pilot Profile blocker.
high

Artifact-first review assumes unnamed surfaces satisfy UJ-2

§8.2, FR-21/FR-22
Engineering may ship JSON dumps and call FR-21 done, or block on an unscoped UI.
Fix: Named artifact schema plus named existing surface or CLI that demonstrates UJ-2 end-to-end.
